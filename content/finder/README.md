# Finder data (P6)

The site's guided finder reads two files. Both are generated by `tools/export_finder.py` from the
tested question tree (`research/finder-test/tree.py`), its examples (`examples.yaml`) and the entry
pages. Don't edit them by hand.

```bash
python3 tools/make_entries.py     # first, if the entries or tags changed
python3 tools/export_finder.py    # stops with an error if any path is too big or too small
```

**`finder-tree.json`** holds the questions. Each question has `question` and `answers`, and each
answer has:
- `label`, plus its `example` and, where the wording could mislead, `explain` (R24);
- `entries`: the outline numbers of the entries left after this answer, given the answers before it;
- `needs_confirming`: for each of those entries that is there only because of a finder value that
  still needs confirming, the field names (the shortlist shows ⚑ on that card);
- `tick` (on two answers, R29): instead of another question, a step where people tick several values
  of one finder tag (`field`), e.g. every material they are gluing; an entry stays only if it has
  *all* the ticked values. `anything` names a value that matches whatever is ticked ("any solid
  parts"); those entries are shown in a separate, folded group;
- `next`: the next question. A last answer has no `next`, and its `entries` are the shortlist
  (always 3-10 entries).

**`finder.json`** has one record per entry: `num`, `page` (the file name in `content/entries/`,
which is also the page address), `title`, `description` (the one-line summary for the card),
`family`, `other_families`, `finder` (the fixed values, for the tick-box panel and the "Made of" row:
`made_of` is the one hand-set field it carries, R37), and `needs_confirming` (which of those values
need confirming). `export_finder.py` stops if an entry has no `made_of` material.

*Decision for review (D16-D17 in `PROJECT.md`):* the tree is saved with each answer's entries
already worked out, rather than as rules the browser would run. The rules then live in one place
(`tree.py`, which is tested), and the finder page only has to follow the answers. "I'm not sure"
can use the entries of all the answers together. The files must be re-exported whenever the
entries, tags or questions change; the site build will do this.
