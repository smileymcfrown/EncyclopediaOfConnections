## Problems met, and how to avoid them next time

- **The app's chat history.** Twice (2026-10-22 and 2026-11-02) the app stopped showing this session's
  recent messages, and on 2026-11-02 one of the owner's messages did not arrive. The work itself was never
  affected: it is all in commits. If this happens again, start a fresh session with the prompt in
  `research/prompts/05-after-phase-5.md`; everything needed is in the repository.
- **Container resets.** The cloud container can be reset while a session is idle. Scratch files go;
  commits stay. Commit and push work as it is done, and keep anything worth keeping in the repository
  (as `tools/find_printables.py` and `content/media/review/r39-printables.yaml` now are).
- **After a reset:** the system Python's Pillow can be broken (use `python3 -m venv` in the scratchpad and
  `pip install pillow pyyaml==6.0.1`), and the site needs `npm ci` in `site/` (and in `tools/renders/`
  for renders) before `npm run build`.
- **Usage limits** stopped agents three times; resuming them after the reset with a message worked, and
  their partial work was kept.
- **Blocked sites.** Wikimedia blocks this machine (picture search and copying run as GitHub workflows:
  *Find pictures*, *Fetch pictures*); Thingiverse and MakerWorld refuse requests; Printables works through
  its API. `gh api` works for GitHub.
- **A command that kills its own shell:** `pkill -f <pattern>` run in the same command line matches
  itself. Stop processes by their process ID instead.
- **A cache file was committed** by accident (`research/finder-tags/__pycache__/`); it is now untracked
  and ignored.
